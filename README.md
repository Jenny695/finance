# 知衡 · 理财产品查询与研究平台

面向普通投资者的本机网页应用：产品查询、净值与风险图表、净值与费用五维研究图与补充材料评估、产品对比、来源追溯，以及首次数据接入配置。HTML + Tailwind CSS + JavaScript + ECharts，Vite 同时提供本机数据 API。

## 当前评分与分类（2026-10-29）

已审阅新增236字段和实际导出表，活跃清单筛选为24项（本次21+沿用3项），按7次请求覆盖核心净值、6类费用、收益、风险、效率、4类净资产配置。无有效值直接隐藏，经理/公司指数和复杂专业字段不混成产品评级。逐字段理由见[审阅表](docs/indicator-selection-236.json)。

五个目标维度：**净值增长25%、回撤控制25%、波动稳定20%、收益风险效率15%、费用负担15%**。优先真实变化的复权净值，累计净值不代总回报；恒定单位/复权净值不记低风险高分。费用仅按已知、单位明确项目评分，缺失不是免费，维度有效权重按费用子项覆盖折算。阈值自建，非行业信用或适当性评级，资料不足不保证五项都有分。详见[完整公式与限制](docs/simple-scoring.md)。

主查询新增“导入超级命令结果表（不取数）”，直接读取用户本机XLSX。默认自动识别%符号；无单位纯数先保留，确认单位后用同一报告重算，不重发收费查询。原件/实际数据不提交Git，仅保存私有报告。配置比例同日、明确单位才画图，不强制100%或硬评安全性。

真实样本的236列中仅17列非空，且18条日期的净值均相同；不能将重复快照画成完整历史评分。应取得真实历史净值或净值实际更新日，而不是继续堆静态字段。接口函数/Excel有字段不等于每只产品数据完整。

目录仍为公募27490、券商32966、银行148867、信托139618，共348941，券商下划线代码合法。更新代码保留.env/.local/import-files，再双击start-finance.cmd；无新增依赖。首次Excel导入的浏览器依赖已在Vite启动预优化，避免开发服务临时重载丢失文件选择。

## Windows 开始使用

需要 Node.js **22.12+**（已验证24.19.0）和 npm。

1. 从 GitHub 下载最新版 ZIP 并解压，进入含 `package.json` 的那一层目录。
2. 如果旧项目已配置 Token，仅在自己电脑把旧 `.env` 和 `.local` 文件夹复制到新项目根目录。不要发送聊天或上传 GitHub。
3. 在该目录地址栏输入 `cmd`，运行：

```sh
npm ci
npm run dev
```

在浏览器打开终端显示的 Local 地址。保持终端运行。构建 `npm run build`，生产产物本机预览 `npm run preview`，自动检查 `npm test`。

服务默认绑定127.0.0.1；API同时检查远端地址、Host和Origin，只供本机单用户研究。尚未实现公网多用户权限隔离，不直接作为公网金融平台部署。

## 普通用户查询流程

1. 首页“产品查询”支持名称、机构、代码搜索，产品类别与风险筛选、关注、2—4只产品对比。
2. **演示体验**：4只产品均为合成数据。净值图、收益、风险和七维评分使用相同序列重新计算，不使用原先的固定占位评分。对应原持仓页为演示，不是用户实际银行持仓。
3. **我的 iFinD 数据**：使用本机 `.env` 里的 Token 与类别净值模板。配置了凭据时首次默认进入该模式；可手动切换回演示。模式间不会混合对比或失败回退。
4. 银行理财已预置用户从官方超级命令提供的字段：

```python
THS_DS('YH0000434.YH','ths_unit_nv_fund','','block:latest','2026-09-16','2026-10-16')
```

完整代码是 **`YH0000434.YH`**（不是早期截图中误读的较短代码）。平台用 `date_sequence`，单位净值字段 `ths_unit_nv_fund`，请求参数保留 `block:latest`，但缺失值处理强制 `Fill:Blank`。日期由网页选择，自动转换为官方日期序列格式。

5. 点击预置产品，或在“我的 iFinD 数据”输入该完整代码，选择区间，点击“查询并分析”。一次显式操作发起一次授权查询，可能消耗额度。缓存5分钟，相同并发请求复用，不自动重试；错误时不显示伪造的真实数据。
6. 产品页展示净值走势、最大回撤、年化换算、波动、七维评分、通俗说明及具体来源。单位净值长期不变时，明确提示不能据此推断零收益或零风险，不解释相应年化统计。资料不足时以资料准备度、缺项与观测质量图代替空白评分图。合成样本提供底层资产饼图与赎回规则用于体验。
7. 当前仅预置一条来自用户截图的目录信息，名称也标记待核对。**这不是iFinD全市场产品目录。** 真实名称搜索仅覆盖已导入目录；知道准确代码时可按配置好的类别模板直接查询。

## 首次连接与扩展类别

### 本机凭据

将 `.env.example` 复制为 `.env`，填写 `IFIND_REFRESH_TOKEN` 或 `IFIND_ACCESS_TOKEN`，然后重启服务。不使用 `VITE_` 前缀变量；不接收账号密码作为HTTP Token。Token只由后端向官方 `quantapi.51ifind.com` 发送，不返回浏览器或写入目录文件。

[官方 Windows 接口包](https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/download.html)解压后：超级命令 → 工具 → refresh_token 查询。网页登录账号不等于所有数据权限。用户已提供本机股票行情查询成功的截图；银行理财字段已由官方生成函数确认，**真实银行理财净值响应仍需在用户本机验证**。云工作区没有用户本机Token，不声称已完成云端授权取数。

### 类别净值模板

进入“数据连接”。银行理财已预置单位净值模板，其他公募基金、券商资管、信托、其他资管类别可独立添加模板；不能假设一个字段覆盖所有类别。

从官方超级命令选一只该类别产品和一个真实净值指标，选择“不运行，输出请求函数”，复制 **THS_DS六字符串参数函数** 到页面，点击“识别官方查询函数”。确认净值口径、分红、费用、采样频率后保存。解析器不执行代码，不接受登录函数、密码或Token。高级入口保留官方HTTP JSON配置。

未知分红时单位净值不作为总回报评分。预置银行模板的费用、币种、采样与分红还未核对，`basisConfirmed:false`，只展示净值及指标，不擅自生成研究分。保存模板必须对照原文确认相关口径。

### 名称搜索的产品目录

“数据连接”可导入官方产品目录 CSV（自动识别UTF-8、GBK/GB18030、UTF-16，单次1.5MB/最多10000只，支持分批upsert）。在网页映射代码、名称、机构等列。名称和代码必填；未知风险、币种、资产分类留空。不会自动把银行理财设为固定收益或R2。

示例列结构：

```csv
code,name,issuer,type,riskLevel,currency
```

`type` 仅接受 `fixed/mixed/cash/equity`，`riskLevel` 仅接受 `R1—R5`；可不导入可选列。类别在上传时选择，同一批应属于同一类别。目录存本机 `.local/finance.sqlite`；类别模板和原文映射保留在 `.local/catalog.json`，Git忽略该目录及 `.env`，发布代码不会包含这些私人配置。首次配置后查询无需再填写JSON。

## 产品数据库与批量同步

侧栏进入“产品数据库”：

1. 从iFinD按产品类别导出真实目录，至少包含完整代码与名称；选择CSV并映射列，未知字段留空。较大CSV自动识别UTF-8、GBK/GB18030、UTF-16及逗号/制表符/分号分隔；导入前全文件严格检查编码，表头与正文使用相同编码流式读取，每1000条独立提交，单文件最多100MB / 100万行。按代码更新，不重复累加。已成功提交批次会保留，后续批次出错可修正重导；这不是全文件原子导入。
2. 在“数据连接”配置每个类别的真实净值模板；不把银行理财模板当作公募基金等所有类别通用。
3. 在数据库页选择产品类别、名称或机构筛选和日期，点击“预览同步范围”。页面显示可同步产品数及缺模板的排除数，预览不调用iFinD。范围或目录改变须重新预览。
4. 确认本次额度使用，创建任务，再点“继续未完成项”。当前页面逐只推进，每次成功保存净值、官方附加指标、计算结果、区间和来源；失败暂停、不自动重试失败项。暂停或离开页面停止后续推进，已发出的单次请求仍会完成。返回或重启后继续未完成项。
5. 产品详情选择**与入库时相同的日期区间**，点击“读取已入库”，无需再次联网查询；保留来源获取时间与报告保存时间。新查询使用“查询并分析”。目前不从不同区间的碎片记录自动拼接分析。

SQLite数据库位于 `.local/finance.sqlite`，使用WAL。目录从旧JSON首次自动迁移，保留原文件，以后以数据库目录为准。升级请先关闭自己启动的服务，再复制整个 `.local` 文件夹和 `.env` 到新目录；不要在服务仍写库时只复制单独的sqlite文件。首次运行自动建库，无需另装数据库软件（Node >=22.12内置SQLite，已在24.19验证）。

净值按凭据指纹、模板口径与日期去重，分析报告按账户指纹、模板、代码和完整区间保存。换Token或改模板后不会自动暴露/混用旧口径报告；当前是指纹隔离而不是真实用户账户系统。数据库不含Token，但含授权行情；不要上传GitHub，公开再分发需取得对应许可。

### 官方最大回撤率与平台计算值

用户再次从官方超级命令提供：

```python
THS_DS('YH0000434.YH','ths_unit_nv_fund;ths_max_retrace_rate_all_fund',';','block:latest','2026-09-16','2026-10-16')
```

预置银行理财请求现支持一次返回两个指标，保留两项独立空指标参数。旧的默认银行模板可兼容补入该字段；自定义银行模板可在“产品数据库”点击启用。如果附加字段无权限导致整次查询失败，可在同页选择“仅查询净值”后手动重查，不会自动降级重试或额外消耗额度。其他产品类别需在官方工具独立确认。网页解析器支持净值在首位的双指标函数；回撤不能作为净值。

- `ths_max_retrace_rate_all_fund`：保存并绘制官方接口**原值**，允许零、负值和空缺。不擅自乘100、取绝对值、断言统计窗口，也不据字段名宣称它与当前观察区间一致。单位、窗口、正负号尚待核验，暂不参与评分。字段未返回时明确提示，不拿平台计算值顶替。
- 平台回撤：根据有效净值独立计算并绘图，展示峰值/谷值及区间。单位净值有分红或口径未知时，不将其解释为真实总回报风险。官方回撤率不与平台回撤混合计算。
- 存储范围当前为目录、有效历史净值、已配置官方附加指标和分析快照。不是下载iFinD的所有字段、全部历史、所有市场。缺少全量目录、其他类别模板或账号权限时仍不能完成全市场入库。
- 大规模全量同步需持续运行及足够配额，单产品请求不代表单点额度。任务可重复创建以更新已有区间；当前未实现定时后台增量调度、历史全版本审计或无人值守同步。

此版本先完成本机单用户数据底座。供多位投资者公网查询还需要服务器、独立账户鉴权、权限隔离、备份、配额调度和数据展示许可，不能把启动本机页面等同平台已上线。

## 产品综合查询：分类指标 → 有效评分 → 加权参考分

侧栏“产品综合查询”或首页“我的iFinD数据”中的产品代码/卡片可进入 `/#/analysis/<代码>?category=<类别>`。一次输入代码、类别和日期，默认选择全部83项指标、12个用途分类。点击“查询分类指标并评分”后按组推进，不要求用户为每个空字段重新验证产品。

- 所有83项保留分类和状态。成功响应中的空值直接显示“无有效数据”，继续查询其他分类，不填0、不插值；请求失败、尚未查询、未选择与格式问题分别标明。
- 支持按分类筛选、只看有数据、原值走势图、七维评分图、可评分派生指标及公式、来源和完整报告导出。
- 已有类别模板和产品元数据可复用。口径明确且净值样本满足规则时，自动计算收益/回撤/波动的指标分与维度分；原始净值、规模、久期等不简单按数值越大越好打分。
- **已覆盖维度综合参考分 = Σ(有效维度分×权重)/有效权重合计**。缺失项不当0分，真实0分仍参与。即使不足完整门槛，也显示已有有效维度的加权参考分，同时显著展示权重覆盖率、有效维度数与缺项。只有原有≥80%及核心维度规则满足时才显示“完整综合分”。全部无评分依据时仍不编造数字。
- 例如只有收益20%、风险25%有效，可显示加权参考分及45%覆盖率；不能当成100%覆盖的完整评价。仅资产材料覆盖100分、覆盖10%时同理，不代表投资安全。
- 83项来自用户函数，不代表每只产品都存在全部数据。原始官方指标单位/窗口尚未确认时，仍可查看并入库，但不拿未知量纲直接打分。ESG文本保留为补充，不强行混入金融分。
- 每组最多8字段，已查询组不会自动重试；单组失败继续其他组，连续3组失败暂停避免重复额度消耗。页面可暂停、继续，离开后不推进；已有结果和游标存SQLite `analysis_runs`，按凭据指纹隔离；可按当前产品代码读取最近报告，不重新取数。
- 查询可能消耗额度，以所选分类分组数和iFinD计费为准。用户点击查询才执行；云端未有Token时只列出分类，明确“未查询”，不假称空数据。

新增接口：`POST /api/analysis/start`、`POST /api/analysis/step`、`POST /api/analysis/control`、`GET /api/analysis/report?id=`、`GET /api/analysis/history`。启动创建报告，逐步接口一次处理一组。报告独立于旧高级研究与净值快照，不把测试报告自动当成真实产品证据。

### 产品数量与指标数量的区别

83是可请求字段数，不是产品数，也不保证每只产品83项都有值。17组完成、2项有值、81项为空且0请求失败，表示本次接口响应成功但大多数所选字段无有效值；不能凭空补出七维评分。

综合查询页新增目录选择：展示本机目录总数及当前匹配数，支持按名称/机构/代码搜索、分页和自动填写产品代码与类别。默认不再固定填一只产品；用户可选择目录项，也可直接输入目录外完整代码。名称搜索仅覆盖已经保存的目录，不是同花顺全市场搜索。

当前只预置一条银行理财代码参考，尚未导入全市场目录。要扩充产品，请从iFinD按类别导出产品列表CSV（至少完整代码、名称，机构可选），通过“产品数据库”的已有批量目录导入功能入库。此步骤不需要重新配置已经可用的Token，目录入库也不会自动下载每只产品的全部指标。结果区“查看这N项有效数据”可一键筛选实际返回值。

## 七维指标方案与实测

侧栏“指标方案与实测”列出七个维度的必需数据、已提供字段、建议接口及明确缺项。已整理用户的83项官方生成字段；函数解析最多100项，保留原始参数，不把编码100/101/102解释成百分比或日期窗口。

- 默认先测单位净值、最大回撤和久期；每次最多8字段、一个官方组合请求，需显式确认额度。不自动试遍83项或重试失败请求。
- 逐项显示有值、空值、类型/日期异常与结构待适配。ESG文本等级可以保留、存储；异常列整列隔离，不保留有效前缀冒充完整结果。
- 数值走势按字段独立切换，不把不同量纲叠加；来源、原参数和测试时间随报告保留。报告期/披露日未知时留空。
- 有值不自动评分：定义、窗口、单位、基准、分红费用和产品适用性仍需核对。测试报告单独保存，不污染正式净值与评分。
- 本机命令 `npm run probe:ifind` 仅预览，`npm run probe:ifind -- --live` 才执行默认三项测试；报告在 `.local/ifind-probe-report.json`。云端尚无用户本机Token，真实取数未执行；本次官方站点访问被代理CONNECT 403拒绝，不能视为iFinD业务错误。

完整接口映射、缺项与实际测试结果见 [指标方案报告](docs/indicator-evaluation-plan.md)。基础资料候选接口不会在未确认字段时编造参数发送。

## 评分模型：公开、可复算、有边界

版本 `zhiheng-research-1.0`。页面“评估方法”公开全部模型假设，详情页每项展示公式、权重、证据和缺项。客观计算不代表评分标准是唯一正确的标准。

|维度|默认权重|方法与必需资料|
|---|---:|---|
|收益表现|20%|CAGR按产品类型预设区间映射；须有有效净值及分红费用口径|
|风险回撤|25%|最大回撤60% + 年化波动40%，以公开类型阈值扣分|
|底层资产透明度|10%|报告支持的披露覆盖比例；示例官方报告按明细估值/组合估值计，不等同信用穿透|
|流动性|10%|持有天数、到账时间、开放频率及原文|
|机构资料完整度|5%|许可、登记、年度报告三项完整度；不评偿付能力|
|信息披露质量|15%|说明书、报告、赎回规则、费用、及时性五项|
|同类横向对比|15%|至少5只类型、风险、日期、币种、净值费用口径相同的去重样本|

综合分 = Σ(有效维度分×权重) / 有效权重合计。有效权重至少80%，且收益、风险、披露有效并为正权重，才展示参考综合分。否则展示资料准备度、覆盖率、局部维度分与缺失原因。不把局部高分冒充完整评价。

收益区间、风险阈值与流动性扣分是公开自建参数，不是行业评级标准，未作预测有效性验证。不同类型不直接排名。未知类型、风险、币种、分红口径不擅自补齐。**仅有净值通常无法生成完整综合分**，非净值维度还需要原始披露与同类样本。

- 区间净值变化：末值/初值−1，不复权时不含分红再投资。
- CAGR：(末值/初值)^(365.25/实际天数)−1。
- 最大回撤：max(1−当期净值/此前最高净值)。
- 年化波动：简单收益样本标准差×√年化期数。
- 下行偏差：√(负区间收益平方和/全部区间数×年化期数)。
- 夏普近似（高级工作台）：(CAGR−输入无风险年利率)/波动率，不等同标准算术超额收益夏普。
- 年化至少90天、30条有效观测和频率校验；年化252/365/52/12按真实采样选择。短样本、零波动和频率不一致按规则停止相关计算。
- 空观测不填0、不沿用前值；查询页可过滤空观测并明确计数，过长缺口会使频率校验失败。CSV和高级解析默认严格拒绝空值。

## 高级研究与公开原文

`/#/research` 保留CSV净值导入、按列映射、人工来源确认、权重设置与报告导出。可用 `examples/evidence-template.json` 和 `public/examples/demo-assessment.json` 查看证据结构；合成材料不能用于真实结论。股票`close`联调数据禁止按理财净值评分。

## 验证与限制

`npm test` 覆盖公式基准、数据缺失、分红、权重、同类样本、CSV、凭据边界、公开来源、目录、模板、缓存与并发。浏览器检查覆盖搜索筛选、关注、对比、图表、导出、日期失效、配置与移动布局。真实iFinD联调不能用模拟上游测试替代。

真实登录、银行/券商个人持仓、交易、全自动披露证据采集和公网多用户服务尚未实现。公开数据再分发需确认来源授权。**不构成任何投资建议，过往业绩不预示未来表现，投资有风险。**

目录导入若提示编码不匹配：先用Excel打开原文件，选择“文件 → 另存为 → CSV UTF-8（逗号分隔）”，再在网页重新选择。批量入口可手动切换文件编码，并确认中文列名正常。XLS/XLSX、ZIP和HTML/XML表格不作为CSV解析，不能只修改后缀。自动识别不能保证区分所有兼容编码，有乱码应手选编码或重新导出；不会用替代字符强行写入。目录导入不调用iFinD，也不等于已经同步净值。

离线目录包：把已转换的UTF-8 `code,name` CSV及SHA-256/行数清单放到`.local/imports/`，运行`node scripts/import-catalog-bundle.js`或双击`import-catalog.cmd`。脚本在任何写入前检查全部文件、产品、重复代码和条数；先用SQLite一致性快照备份原数据库，保留已有机构/风险/资产分类/币种/来源等非空资料，再每1000条导入，失败保留已提交批次。无Token、无上游请求、未知资产分类和风险留空。不要将上传目录、清单或数据库提交Git。`.local/imports/manifest.json`为version=1、total及files数组（file/category/rows/sha256），类别不明时使用other，不能仅凭.OF后缀判断为公募基金。

Windows可双击`start-finance.cmd`：检查Node>=22.12，缺依赖时安装；若存在上述目录包，首次自动导入，后续清单相同且数据库仍在时保留原库直接启动并打开浏览器。启动窗口需保持开启。手动需要重导时使用`import-catalog.cmd`。私有目录仅随用户自己的本地包提供，不在GitHub源码中；GitHub源码下载不等于获得此前上传数据。

目录整包替换支持可选`removeProducts`（完整code/name/category清单，上限10000）：不得与新目录代码重叠。全部新目录成功导入后，事务内按旧名称和类别核对并删除指定的旧目录记录；不清空整个类别，不删除历史净值、指标或报告。旧记录被用户修改时拒绝删除并回滚本次删除事务，已完成导入批次保留。导入前仍做一致性备份；再次运行时已不存在的旧代码不重复删除。

无法下载聊天附件时，可直接从GitHub的Code → Download ZIP下载源码。项目`import-files`文件夹内有放置说明：放入本机原始的`全部基金.xlsx`、`银行理财产品(存续期).csv`、`全部(信托产品).csv`、`全部(已成立、未到期).csv`；如需从旧REIT表精确移除旧表独有产品，一并放入`公募REITs.csv`（仅用于替换核对，不加入新目录）。双击`start-finance.cmd`会安装缺少的依赖，再用Node读取实际XLSX或文本CSV，不需要Python/Excel另存或聊天数据压缩包。原文件名需保持不变，同一类别只留一个版本。原始文件与转换清单均不提交Git。准备阶段失败不写数据库；原始文件哈希相同时跳过重复转换，随后沿用离线包校验、备份、精确替换和导入流程。未知类别仍为other；目录不等于完整行情或评分。

目录导入修复（2026-10-29）：券商代码可合法带下划线，例如`JH852135_1.OF`；不会因这类代码拒绝整份文件。新上传四表实测32966只券商中包含91个下划线代码，完整保留。已成立未到期目录若出现无法确认的其他合法代码，另存为待分类，不阻止其他产品入库；若与明确基金/银行/信托目录重叠，优先保留明确目录的名称和分类并记录去重提示。全部基金仍是公募基金，不根据.OF后缀混为券商。
