# 给投资者使用的公网版

公网版包含服务端注册登录、密码scrypt加盐哈希、HttpOnly会话、用户报告隔离及管理员权限。投资者页面只保留首页、产品查询、产品对比、投资知识与个人中心，无演示产品、风险等级筛选或其他资管选项。

## 最简单的长期托管：Render

[打开一键部署](https://render.com/deploy?repo=https://github.com/Jenny695/finance)

1. 注册/登录Render，连接自己的GitHub仓库`Jenny695/finance`，检查部署配置。
2. 使用仓库的`render.yaml`创建服务。配置为单实例与持久化磁盘，保留用户、会话和分析记录。此方案是收费托管，费用以Render确认页为准；不会承诺免费永久运行。
3. 在Render的保密环境变量中填写自己的`IFIND_REFRESH_TOKEN`。不要填写到网页、聊天、GitHub文件或VITE_变量。
4. 等待构建和健康检查通过，复制Render提供的HTTPS网站地址，即可发送给他人注册登录。
5. 管理员用户名为`finance_admin`，密码由Render生成，在服务环境变量`ADMIN_PASSWORD`中查看。普通注册用户不能访问管理接口。
6. 管理员登录后可导入准备公开使用的产品目录；新公网数据库默认不复制本机的`.local`、原始导出文件或个人研究记录。

无需自购域名。Render自动提供HTTPS子域名；以后可以绑定自己的域名。PUBLIC_URL默认读取Render自动提供的RENDER_EXTERNAL_URL。更换域名时设置PUBLIC_URL为新的HTTPS来源。

## 本机开发与管理员

Node.js 24 LTS，`npm ci && npm run dev`。开发服务使用`.local`保留旧目录数据，新增账户和报告按用户隔离。原本的演示昵称不能当成真实账户，需注册新账号。

在本机`.env`中配置ADMIN_USERNAME、ADMIN_PASSWORD后运行`npm run create-admin`，再使用该账号登录。密码至少8位；不要放到命令行参数或公开文件。管理员入口与普通用户页面分离。

生产运行：`npm run build && npm start`。设置DATA_DIR到持久磁盘；生产环境需提供PUBLIC_URL或RENDER_EXTERNAL_URL，且必须为HTTPS。端口由PORT设置。不要公开Vite开发服务器或旧本机单用户接口。

## 数据与权限

- 注册接口只创建investor角色；管理员只能由保密环境配置/本机命令初始化。
- 公网报告按账号ID划分独立存储空间，更新上游凭据不会将记录转给其他用户。其他用户即使知道报告ID也无法读取/修改。
- iFinD凭据只存服务端；普通投资者无目录导入、原始API、单位设置或模板权限。
- 同一服务内，管理员和普通账号共享相同代码、日期、字段及凭据下的官方行情缓存（默认15分钟）；读取缓存不消耗用户接口额度。用户报告、投资计划与登录状态仍独立隔离。凭据更换后不复用旧凭据缓存。
- 默认每用户每天240次、全站每天240次实际分组请求（中国标准时间重置）；修改投资计划、读取报告不耗上游额度。限制可由服务器环境变量调整。
- 密码仅保存scrypt加盐哈希，会话随机生成且数据库仅保存令牌哈希；公网Cookie为Secure/HttpOnly/SameSite=Lax。写请求校验同源，登录/注册限频。
- 无Token时不生成虚构行情，用户仍可注册登录和阅读投资知识。实际数据权限、展示范围与更新日期以配置和响应为准。
- 临时预览链接只用于当前在线进程，停止后失效，不能代替持久托管。预览默认使用独立空数据库，不复制本机凭据或私人记录。

## Windows 本机前后端一起更新

将下载包中的 `UPDATE-FINANCE.cmd` 复制到正在运行的原项目根目录（`.env` 和 `package.json` 同一层），先在旧网站后台窗口按 Ctrl+C，保留 Cloudflare 窗口，再双击运行更新脚本。脚本检查端口已停止；若没有保存公开地址，会提示粘贴当前 HTTPS 网站地址。脚本只更新源码与依赖、重建网页并启动后台，保留 `.env`、`.local`、`.public-data` 和 `import-files`。旧源码备份到 `.source-backups`。下载或构建失败会停止并保留错误，不会假报成功。完成后在浏览器按 Ctrl+F5。

默认单账号每日请求上限已从36次调整为240次，全站仍为240次；显式设置的 `USER_DAILY_QUERY_LIMIT`、`TOTAL_DAILY_QUERY_LIMIT` 继续生效。上限统计的是实际分组请求，不是产品个数；缓存命中不扣额度。账号额度不足和全站额度不足会分别显示。
